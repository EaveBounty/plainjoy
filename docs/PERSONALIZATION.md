# 个性化营养：病况 → 目标 → 权重 → 建议

> 目标不是「替医生开处方」，而是把同一顿饭对不同人的意义算清楚，并把不确定性说清楚。

## 1. 三层结构

```
HealthProfile（病况/孕产/素食/体重/活动量）
  → ConditionPolicy：目标覆盖 + 评分权重 + 禁忌
  → NutrientTargets：合并后的每日目标（冲突时取更严上限）
  → ScoreEngine：16 项加权，数据不足的项退出分母
  → AdviceEngine：今日摄入 → 最多 4 条可执行建议
```

代码：

- `lib/core/health/condition_policy.dart`
- `lib/core/scoring/nutrient_targets.dart`
- `lib/core/scoring/score_engine.dart`
- `lib/core/health/advice_engine.dart`

## 3. 多病况叠加

规则：

1. **上限取更严、下限取更高**；
2. 若下限 > 上限（如 CKD 钾 ≤2500 与高血压钾 ≥3600），**丢弃下限、保留上限**，并在目标卡写明「已按更严格的上限收紧」；
3. 肾病优先：CKD + 孕期/哺乳时，蛋白按体重与透析状态覆盖，不叠加；
4. CKD + 痛风时不再给「水 ≥2500 ml」，液体量交给肾内科。

## 4. 数据不足时怎么办

- 每个营养素按**能量加权覆盖率**判断：<60% → `ScoreStatus.unknown`，权重置 0；
- 全项无数据的评分域权重置 0，总分按剩余域重新归一化；
- 建议引擎对未知项不输出「达标/超标」，只输出「未记录，无法判断」。

这解决了 v0.1 的三个假信号：

- 添加糖 85% 食物无数据 → 仍显示 0 g / 100 分；
- 磷 0% 数据 → CKD 永远「磷达标」；
- 饱和脂肪 96% 缺失 → 永远 0.0%E。

## 5. 建议引擎的排序

1. 孕期/哺乳期酒精（priority 120）
2. CKD 钾/磷超上限（100/98）
3. 高血压钠超 2000（100）
4. 糖尿病添加糖超限（95）
5. 孕期叶酸/碘（95/75）
6. 痛风高嘌呤关键词（92）
7. 贫血铁 + 维 C（85）
8. 通用缺口（蔬菜/纤维/蛋白/钙）

每条建议包含：标题（带数字）、动作、依据、必要时「需就医」。
不输出：诊断、药量、疾病风险百分比。

## 6. 证据与措辞

- 指南 → 「指南」；共识 → 「共识」；机制推断 → 「机制」；
- 所有目标都写「饮食目标，不是处方」；
- 肾病、孕期、痛风急性期、贫血分型，必须保留就医提示；
- 不用「你应该」的 normative 语气，用「最省力的两步是…」。

## 7. 仍未解决

1. 没有分期（CKD G1–G5）、没有用药清单、没有血压/血糖/血脂实测值；
2. 贫血未分型时仍会放大铁权重（已加提示，但未强制确认）；
3. 嘌呤没有 mg 值，只能靠关键词；
4. 孕期没有三 trimester 区分，蛋白统一 +20 g；
5. 个体差异（肠道菌群、药物、活动）无法进入模型。
