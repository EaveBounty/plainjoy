## 1. 用户与定位

### 1.1 目标用户

**主用户**：22–30 岁城市青年，独居/合租，外卖 + 食堂 + 偶尔自炊，有健康意识但没有营养学训练，不愿称重，容易被「记录麻烦」劝退。

**次用户**：健身但不想极端备餐、备考/加班导致饮食紊乱、高血压/糖前/贫血/乳糖不耐等需要饮食管理但不想医疗化的人。

**非目标**：需要临床营养治疗的患者、需要精确药物-营养交互管理的人、以极端减重为目标的人。

### 1.2 定位句

- 对外：**「不是减脂打卡，是营养充足度管理。」**
- 钩子：**「不用称，也知道今天差哪一口。」**
- 深度用户：**「把营养缺口，变成下一餐；把下一餐，变成一只会变好的宠物。」**

### 1.3 设计原则

1. **误差优先**：承认估算误差，显示区间，不制造虚假精确。
2. **少填也有用**：10 秒记录必须能进入评分；不因精度低拒绝保存。
3. **可解释**：每个分数都能下钻到食物、份量、替换建议。
4. **不羞辱**：不足是常态，不是失败；宠物永不死亡。
5. **确定性算数，LLM 只叙述**：营养数字来自食物库与公式，不让模型编。
6. **本地优先**：无账号也能完整使用；AI 是增强，不是前提。

## 2. 竞品结论（摘要）

详见 `docs/research/01-competitors.md`。

- 食物识别已白菜化：Foodvisor 87%、中文菜 91.67%；但能量误差 25–50%，主因是克重。
- 单图碳水 MAPE 56.6%，给真实重量后 20.2%。
- SNAQ 对照双标水：日均低估 25%，个体一致性 ICC = 0.00。
- 已做满：食物库规模、条码、热量/宏量记录 UI、按热量配餐、单日饮食评分、宠物打卡。
- 结构性空白：**缺口 → 下周菜单的约束求解**、可解释充足度评分、低摩擦但承认误差的克重估算、宠物状态↔营养质量多轴映射、Windows/Web 周复盘工作台。
- 漏斗断点：记录断在份量；理解断在评分不解释；计划断在计划与缺口无关；执行断在无因果叙事。

**结论**：拍照是输入加速器，不是核心卖点；护城河是「份量 × 区间 × 校准 × 缺口求解 × 解释」。

## 3. 核心循环

```
记录（≤3 击，给区间）
   ↓
今日缺口（瀑布归因，只给 1 条建议）
   ↓
下一餐/明日补丁餐（约束求解）
   ↓
投喂（食材类别映射）
   ↓
宠物状态（7 日趋势，可点开解释）
   ↓
周报（3 条建议 + 下周 3 个补丁餐）
   ↺
```

**情绪链**：我做了 → 它变好了 → 我知道为什么 → 我明天还愿意做。
**禁止链**：我没做 → 它受苦了 → 我愧疚 → 我卸载。

## 4. 功能规格

### 4.1 首次启动

2 屏 + 1 个常驻出口：

1. **画风选择**：同一只宠物的两种画法（默认/Q），实时切换预览；可跳过，默认版。
2. **使用强度**：`10 秒快速` / `60 秒标准` / `3 分钟精确`；可随时改。
3. **进入首页**，不强制填身高体重；健康档案在需要时再引导。

文案要求：不承诺「精准」，用「大概」「区间」「够不够」。

### 4.2 首页

- 顶部：日期、连续记录、设置入口。
- 宠物舞台：程序化绘制，两套皮肤；idle 动画；点一下说出「今天唯一该改的一件事」。
- 今日分数卡：总分 + 区间 + 三域小环；记录不足时显示「记录不足，暂不评分」。
- 快捷记录：拍照 / 文字 / 常吃。
- 今日建议：1 条，必须包含「具体食物 + 份量 + 预期变化」。
- 今日时间线：早餐/午餐/晚餐/加餐，可展开。
- 底部导航：首页 / 记录 / 计划 / 营养 / 我的。

### 4.3 记录

**输入方式**：

- 文字：自然语言 → AI 解析；无 key 时本地别名/模糊匹配。
- 拍照：选图/拍照 → AI 识别 → 用户确认份量；失败时退回文字。
- 常吃/最近：一键复用。
- 计划：从计划页「标记已吃」。

**份量三档**：

| 档位 | 输入 | 误差预算 | 交互 |
|---|---|---|---|
| L1 快速 | 常吃 chip + 少/中/多 + 剩了 0/¼/½/¾/全 | ±35–45% | ≤3 击，10 秒 |
| L2 标准 | 照片 + 容器/参照物 + 滑块 | ±20–25% | 60 秒 |
| L3 精确 | 秤/量杯 + 剩饭扣除 | ±8–10% | 3 分钟 |

**硬规则**：

- 先给区间，再让用户拖动；绝不问「多少克」。
- 「不知道」永远可用，且不产生负反馈。
- 默认值来自用户自己的历史中位数，不是全国均值。
- 保存后只回「已记录 ✓」，不在记录时评判。
- 每条 item 存 `grams_p10/p50/p90` 与 `estimate_method`。

**容器标定**：

- 内置常见碗/杯/外卖盒/勺；用户可新增。
- 30 秒流程：放空容器 → 加水至常用刻度 → 输入水量或选常见容量 → 保存。
- 存 `capacity_ml`、`tare_g`、`fill_ratio_default`、`shape`、`density_hint`。
- 可复用；可标记「这个碗换掉了」。
- 容器 + 食物类别 → 克重先验；用户拖动后写回个人校准系数。

**参照物**：

- 手掌、拳头、拇指、扑克牌、手机、硬币、一次性碗/勺。
- 中式食物映射：一碗米饭 ≈ 150–200 g；一掌心肉 ≈ 75–100 g；一拳蔬菜 ≈ 100–150 g；一勺油 ≈ 10 g。
- 参照物卡片可离线查看，不依赖 AI。

### 4.4 营养仪表盘

**信息架构**（自上而下）：

1. 总分 + 区间 + 一句话结论。
2. 三域环：食物组 / 营养素 / 限制项。
3. 「这 18 分丢在哪」瀑布：基线 100，逐项扣分，右侧 `-8`。
4. 16 项子弹图行：实际 vs 目标 vs 适宜区间；按扣分排序。
5. 钠专章：总钠、隐形来源、盐换算、替代建议。
6. 微量营养素缺口：铁/钙/VD/叶酸/B12/钾等。
7. 趋势：7 日 / 30 日，带区间带。
8. 日历热力：月视图，颜色 + 斜纹 + 箭头三通道。
9. 周报/月报：3 条建议 + 下周 3 个补丁餐。

**日/周/月**：

- 日分默认收起，周报为主。
- 周分 = `0.75×均值 + 0.25×28 日基线 − min(5, SD/3)`。
- 月分 = 最近 4 周中位数；趋势只做箭头。
- 记录不足的天不计入周分，但显示「本周记录 5/7 天」。

**图表**：

- 必须：子弹图行、6 轴雷达（仅食物组、轴序固定）、堆叠条、日历热力、趋势线+区间带、瀑布、蜂窝索引。
- 禁止：手机端桑基图、指针仪表盘、>6 轴雷达、16 个并列迷你图、3D 饼/环、双 Y 轴、彩虹热力、词云、逐条掉落瀑布、平滑曲线掩盖波动。

**非焦虑表达**：

- 整条进度条绝不变红；超出段用斜纹延伸。
- 不足用蓝，偏多用琥珀，明显偏多用深红 + `↑↑`。
- 评价单位从「天」拉到「周」；一天只给 1 条建议。
- 日终才聚合反馈，记录时只回「已记录 ✓」。

### 4.5 餐食计划（关键功能）

**输入条件面板**（常驻，改了立即重算）：

- 目标：下一餐 / 明天 / 未来 3 天 / 本周。
- 设备：仅电磁炉 / 微波炉 / 电饭煲 / 烤箱 / 空气炸锅 / 不做饭。
- 时间：≤10 分钟 / 20 分钟 / 40 分钟。
- 预算：≤15 / 25 / 40 元/餐。
- 味道优先级：味道优先 / 均衡 / 健康优先。
- 懒度：不想切菜 / 可以洗切 / 愿意备餐。
- 忌口/过敏、健康档案规则、剩菜、季节。
- 偏好：食材/菜品/抽象特征 5 星。

**输出**：

- 下一餐 1 个主方案 + 2 个替换。
- 未来 1–3 天 3–5 个「补丁餐」，不是 21 餐全计划。
- 每餐：菜名、份量、预计营养增量、钠、时间、设备、步骤、成本、替换选项。
- 每餐必须说明「补哪个缺口」：如「补铁 +3.2 mg，补纤维 +6 g，钠 +420 mg」。

**算法**：

1. 从评分引擎取 top 3–5 缺口（按 `penalty × actionability × evidence × safety` 排序）。
2. 从食谱/食物图筛候选：满足设备、时间、预算、过敏、健康规则、偏好。
3. 确定性优化：目标 = 缺口覆盖加权和 + 偏好 − 钠/超加工惩罚；约束 = 健康/设备/时间/预算。
4. 贪心 + 局部搜索；无解时按「味道 → 时间 → 设备 → 预算」放宽，显示取舍。
5. LLM 只生成解释、菜名变体、步骤润色；营养数字来自库。

**防重复**：同一菜品 7 天内不重复；每周最多 3–5 个补丁餐；允许「换一个」。

### 4.6 健康档案

字段：出生年、性别、身高、体重、活动量、目标、过敏、疾病、饮食模式、孕期/哺乳、实验室指标（可选）、用药（可选，仅提示交互）。

规则表（四类）：

- **避免**：如痛风 → 高嘌呤内脏/浓肉汤；乳糖不耐 → 普通奶（可用无乳糖替代）。
- **限制**：高血压 → 钠 ≤2000 mg（理想 1500）；糖尿病 → 添加糖、精制碳水、餐后血糖负荷。
- **推荐**：贫血 → 血红素铁 + VC；骨质疏松风险 → 钙/VD/蛋白质；素食 → B12 强化/补充。
- **需就医**：肾病蛋白/钾/磷、孕期、药物-营养交互、明显症状。

UI 必须显示「这不是医疗诊断；有症状请就医」。规则可解释：每条提示点开显示依据与适用条件。

### 4.7 食物偏好表

实体类型：

- 具体食物/食材（`food`）。
- 菜品（`dish`）。
- 抽象特征（`trait`）：辣、咸、甜、酸、油、麻、软、脆、烫、凉、大份、清淡。
- 场景（`context`）：家里 / 外卖 / 食堂 / 餐厅。

评分：1–5 星；另有 `avoid`（再也不吃）与 `allergy`（安全硬约束）。

采集：

- 显式：偏好页搜索添加。
- 隐式：用户说「我喜欢/不喜欢」时，AI/本地规则抽取 → 弹确认「记成 4 星？」。
- 行为：计划被替换/跳过/吃完了 → 作为弱证据，不自动改星级。
- 证据计数：一次提及只记 3 星 + `evidence=1`；重复 3 次才升到 4/5；用户可手动覆盖。

展示：表格 + 筛选 + 排序 + 批量编辑 + 导出；显示「为什么记成这样」（来源、次数、最近一次）。

### 4.8 宠物

**四轴**（0–100，7 日滚动）：

| 轴 | 驱动 | 可见表现 |
|---|---|---|
| 活力 | 能量/蛋白质/铁/B12 | 动作频率、耳朵/尾巴、打哈欠 |
| 皮毛 | 蛋白质/omega-3/锌/VA | 毛发光泽、掉毛粒子、舔毛 |
| 心情 | 饮食多样性/连续记录/睡眠 | 表情、靠近/躲远、玩耍 |
| 水分 | 饮水/钠 | 望水碗、舔嘴、浮肿感（不显示数字） |

**硬规则**：

- 体型恒定，不随 BMI 变。
- 永不死亡、永不生病；负面只做「需求信号」。
- 单日低分只让它「困」，不生病；状态看 7 日趋势。
- 一天最多 1 个需求信号（argmax + 阈值 0.6）。
- 点宠物 → 一句解释 + 一个可执行建议。
- 不做排行榜；社交只做送食材/合影。

**投喂**：

- 用户计划/实际饮食 → 抽象为类别：汤 / 炒菜 / 蔬菜 / 主食 / 水果 / 奶 / 肉蛋豆 / 零食 / 饮料。
- 投喂动画 + 弹出 `+蛋白 +12 g / +纤维 +4 g / -钠 -300 mg`。
- 投喂是可视化，不是第二套经济；不能靠投喂刷分。

**经济**：

- 单币「爪印」；日上限 70，月约 2200。
- 零抽卡、零 premium 货币、零体力。
- 普通宠物 480（≈7 天）、稀有 1200、剧本 180/章。
- 直购 ¥6/12/18；会员 ¥15 月 / ¥98 年（不给数值优势）。
- 未成年 <14 关闭付费；14–18 按限额。
- 宠物命名后永不进付费墙。

**首版宠物**：三花猫、中华田园犬（默认）；橘猫、狸花猫、柴犬、柯基（可解锁）。10 个动画状态：idle / happy / eat / full / sleepy / sleep / thirsty / lowEnergy / celebrate / transition。

**技术**：`PetRenderer` 接口 + `CustomPainter` 程序化绘制，两套参数；预留 Rive 实现。状态机与皮肤解耦，CI 校验 10 个状态齐全。

### 4.9 双主题

**默认版：编辑式体检报告**

- 底 `#FAF8F5`，卡 `#FFFFFF`，墨 `#17191C`，发丝线 `#E5E0D8`。
- 标题衬线（Noto Serif SC），正文无衬线，数字 tabular。
- 圆角 4/8/12；几乎无阴影；交互色 = 墨（黑底白字）。
- 图表 1.5px 方头线，3 条参考线，数值标点。
- 语气：陈述句、无感叹号、脚注。

**Q 版：黏土糖果绘本**

- 底 `#FFF9F2`，墨 `#3A2E2A`，主强调雾紫 `#6E56CF`，蜜桃 `#FF9066`（仅填充）。
- 圆角 8/16/24/全圆；1.5px 描边；硬阴影 `0 3 0`。
- 圆体字；图表 3px 圆头线、点网格、圆雷达。
- 动效 `easeOutBack`，overshoot ≤1.05。
- 三条红线：不用 Comic Sans 类字体；不用彩虹渐变；可爱只在陪伴层，结论层永远陈述句。

**语义色恒定**：达标绿 `#2C7A57`、不足蓝 `#3E6FA8`、偏多琥珀 `#A85A1B`、明显偏多深红 `#7E2A2A`、未知灰。

**切换**：设置页开关；首启询问；切换不重启；所有页面通过 `ThemeExtension` 取 token；72 张 golden（12 页面 × 2 主题 × 3 状态）。

### 4.10 AI

- 模型：`deepseek-flash`（Vision + JSON，1M ctx），可配置为 `deepseek-v4-pro`。
- 关闭 thinking（默认开启会慢/贵）；JSON mode；超时 20s；重试 2 次。
- 用途：文字/照片 → 结构化食物条目；计划解释；周报叙述；偏好抽取。
- 不用途：营养数字、评分、医学建议。
- 无 key / 无网：本地别名/模糊搜索 + 规则解析；完整功能可用。
- 密钥：原生 `flutter_secure_storage`；Web 仅 sessionStorage，默认不记住；UI 脱敏预览。
- 隐私：只发食物描述/图片，不发健康档案；提供「本地模式」开关。
- 成本：Flash 单次约 ¥0.003；显示 token 与估算费用；月预算上限。
- 托管接口：`AiBackend` 抽象，预留 `CompanyGatewayBackend`（未来公司平台 AI API），不写死 BYOK。

## 5. 评分规范 v1

### 5.1 16 项与权重

### 5.2 总分

```
D_A / D_B / D_C = 域内加权平均
Total_raw = 0.40·D_A + 0.32·D_B + 0.28·D_C
Total = min(Total_raw, gates)
```

守门：

- `D_A<40 → ≤55`；`D_A<25 → ≤45`。
- 钠分<30 → ≤70。
- `D_C<30 → ≤60`。
- 超加工供能 >50%E → ≤75；>70%E → ≤60。

### 5.3 资格门槛

全部满足才评分：

1. 能量 ≥70% EER。
2. ≥2 个进食场合。
3. ≥5 个食物条目。
4. ≥3 个食物组。
5. 钠/糖/脂肪至少 2 项可估。

否则「记录不足，暂不评分」，不计 streak、不计周分。

### 5.4 不确定性与聚合

- 每个克重区间做 500 次分层蒙特卡洛（同一食物共用抽样）。
- 输出 p10/p50/p90；区间 >30 或记录不足 → 不给总分。
- 周分 `0.75×均值 + 0.25×28 日基线 − min(5, SD/3)`；n<3 时基线 60。
- 月分 = 4 周中位数；趋势只做箭头。
- 总分取整/5 分档；不显示小数。

### 5.5 防刷分

- 补剂所有营养素计 0。
- 强化食品按 50%；某营养素 >50% 来自强化 → 单项封顶 60。
- 分离/添加纤维按 50%。
- 加工肉按 50% 计入蛋白组。
- 超加工 NOVA4 设总分上限。
- 记录少不给高分。

### 5.6 钠

- `钠 mg = 克重 × 钠浓度 / 100`。
- 调味品单列：酱油 10 ml ≈ 1.6 g 盐；豆瓣酱 10 g ≈ 1.5 g；蚝油 10 g ≈ 1 g；味精 1 g ≈ 0.5 g。
- 外卖默认 ×2.5；喝汤 100%，不喝 20%。
- 包装食品看标签；无标签标「缺失」，该项不计入分母。
- 高血压档案：1500 理想 / 2000 达标 / 3000 归零。
- 钠钾比只展示，不计分。

class PetAxes {

## 10. 验收标准（v1）

1. 冷启动 <1.5 s（中端 Android，release）。
2. L1 记录 ≤3 击 / 10 s；保存后评分 <100 ms。
3. 16 项评分全部可下钻；总分有区间；记录不足不给分。
4. 钠专章能拆出「调味品/外卖/汤汁/包装」四类来源。
5. 计划页改任一条件，3 秒内重算 3 个补丁餐；每餐有缺口增量。
6. 健康档案至少 8 种情况触发正确规则；每条规则可解释。
7. 偏好表支持 5 星 + avoid + 证据计数；AI 抽取需确认。
8. 宠物 4 轴由 7 日分项驱动；点宠物给 1 条可执行建议；永不死亡。
9. 双主题切换不重启；12 个页面 × 2 主题 golden 通过；语义色不变。
10. 无 key 时全功能可用；有 key 时文字/照片解析可用；失败可降级。
11. 导出 ZIP（JSON + 照片），可在新设备恢复。
12. `flutter analyze` 0 error；核心评分/计划/份量单测覆盖；Android + Linux + Web 构建通过；Windows CI 通过。
